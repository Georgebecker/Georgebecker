## 👋 Sobre mim

Trabalho com tecnologia com uma regra simples: **documentação clara, dados de qualidade e verificação antes de qualquer conclusão**.

Curso **Gestão em Tecnologia da Informação** (Estácio) e a trilha **Análise de Dados** (SCTEC), e aplico os estudos em projetos próprios — **sempre com teste e medição, nunca com promessa**. Também desenvolvo **sites em WordPress** (de classificados imobiliários a sites institucionais), com gestão de TI e ambientes em nuvem.

Um tipo de projeto se repete: **dado público brasileiro** (Banco Central, IBGE, ANP, saúde) virando pipeline em Python, API e painel em que cada número tem órgão, período e data de coleta.

## 🔁 Como eu trabalho
Todo projeto nasce do modelo [**projeto_loop**](https://github.com/Georgebecker/projeto_loop) e segue **Loop Engineering**: hipótese → mudança pequena → teste → métrica real → decisão **ACEITO/REJEITADO**, registrada no `log_loop.md`.

- **Commits pequenos e descritivos** — cada mudança com um propósito claro;
- **Documentação junto com o código** — README que explica o *porquê*, não só o *como*;
- **Verificação antes de concluir** — todo projeto próprio tem teste ou medição que sustenta a afirmação.
## 🚀 Convite à interação
Este perfil não é vitrine: é código aberto para ser lido, testado e questionado.

- **Iniciantes** — há tarefas simples espalhadas nos repositórios (melhorar uma mensagem de erro, escrever o primeiro teste de uma função). Abra um Pull Request pequeno, mesmo com dúvida: eu reviso, explico e ajudo. Comece pelas issues com a etiqueta `good first issue`.
- **Colegas de programação** — encontrou gargalo, brecha de segurança, consulta SQL lenta ou decisão de arquitetura discutível? Abra uma Issue ou um PR. Feedback técnico direto vale mais que elogio.
- **Recrutadores e visitantes** — estes são projetos reais em manutenção, não exercícios copiados: cada um tem código, teste e histórico no `log_loop.md`.
## ⚠️ Transparência e limitações

- **Cards de terceiros:** as estatísticas vêm de serviços gratuitos (`github-profile-summary-cards`, `github-profile-trophy`, `shields.io`). Se um deles cair, a imagem simplesmente não aparece — já substituí dois serviços por causa disso e o comentário no topo deste arquivo guarda o histórico.
- **Estágio declarado:** `ipca-postgres-docker` é rascunho; os demais variam entre MVP e projeto publicado. Nenhum é apresentado como produção.
- **Sites com template:** em IMOXS e FS Imobiliária a base é template; o trabalho foi adaptar, publicar e manter.
- **Sem SLA:** são projetos de estudo e uso próprio, mantidos em ciclos — não há promessa de disponibilidade nem de prazo.
